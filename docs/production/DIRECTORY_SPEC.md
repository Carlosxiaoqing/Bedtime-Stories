# 目录与交付规范

2026-11-12用户明确要求：Outputs只放按日期整理的单集输出；全集剧本、角色图库和可复用资料放回项目根目录下的对应目录，后续统一从那里加载。本规范覆盖旧文档中把所有制作材料放入Outputs的约定。

```text
Bedtime-Stories/
├── 02_100集剧本/
│   ├── 用户长稿v4/结构化JSON/      # 当前004–100的唯一口播稿源
│   └── 阅读与审校/               # 合集阅读页、v2/v3历史稿、核对和校订资料
├── 03_素材与参数/
│   ├── 用户长稿v4角色图库.json    # 角色、服装、真实路径及摘要的权威索引
│   └── 角色参考图库/v4/          # 共用角色原图、提示词与初始化记录
├── episodes/ep004/v001/          # 原图、音轨、分镜、字幕、字体、工具及检查证据
├── docs/production/              # 共用规范与维护记录
├── local/                       # 当前生产工具
└── Outputs/
    └── 2026-11-11/
        └── ep004-v001/
            ├── ep004.mp4
            ├── ep004_clean.mp4
            ├── cover.png
            ├── 发布文案.md
            └── README.md
```

`02_100集剧本`、`03_素材与参数`、`episodes`与`Outputs`都是项目根目录下的同级目录。共用资料只有一个正式加载入口，不从日期交付目录找角色图，也不从合集快照替代JSON改稿。

每次新制作的交付日期按北京时间启动日确定，跨天运行沿用启动日，新一天的新任务建新日期；整理旧交付不改原制作日期。每个日期目录只含对应单集交付文件夹。制作源、预览试片、缓存、工程ZIP、全集稿件和角色资料保存在对应工程或共用目录。交付README链接到工程，便于查找原图与来源。

迁移或替换交付时，检查成片、封面与正文是否来自同一版本；保留工程版本证据，避免把旧候选、旧字幕预览混进日期交付。当前004的5个交付文件直接来自已认可v001，视频及封面字节未改变。

本次已迁移10个目录，保留原内容与迁移前文本备份；路径映射、逐文件摘要和校验结果见[目录整理记录](维护记录/2026-11-12_目录整理/RECORD.md)。旧归档ZIP代表当时快照，当前生产加载以目录内文件和权威角色索引为准。

## 工具用法

全集阅读导出写入`02_100集剧本/阅读与审校/<独立版本目录>`。`export_story_scripts.py`与`export_long_scripts.py`会拒绝将全集写入Outputs。

长稿工作目录使用`episodes/epNNN/vNNN/`。004已验证的渲染入口把工作源与最终交付分开：

```sh
.venv/bin/python local/render_long_episode.py --output-dir episodes/ep004/v001 --delivery-dir Outputs/<本次日期>/ep004-<新版本>
.venv/bin/python local/check_long_episode.py --output-dir episodes/ep004/v001 --delivery-dir Outputs/<本次日期>/ep004-<新版本>
```

上述为目录参数示例，不是授权重渲染或批量制作。覆盖前先保留版本；当前整理不重新生成配音、插画或视频。001复现由`local/run.py`自动将中间文件写进`episodes/ep001/本地复现/`，只复制最终视频、封面与正文到日期交付目录。
