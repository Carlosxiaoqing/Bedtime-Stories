# 晚安绘本馆｜制作总手册与AI交接规范

版本：1.1（精简交付版）。整理日期：2026-11-09。唯一已验收基准：第001集《小兔子皮皮的晚安星光》第二版。

## 1. 任务定义、阅读顺序与交付边界

这是一个可以复制到其他目录、交给其他AI或剪辑人员继续使用的生产包。它包含100集完整文字剧本、已验收首集的全部关键媒体、原始分句配音、素材来源、精确参数、参考程序、离线安装文件和检查记录。

100集已经包含第001集；第002–100集为99个新故事。后99集当前完成的是剧本、分镜、每镜绘图提示词与制作数据，尚未生成对应的891张新图或99条成片。第001集的九张图和媒体确实存在；不得把后续未制作的素材写成已有文件。

接收AI的阅读顺序：

1. 阅读本文件和00_交接入口/把这段话发给AI.md。
2. 查看03_素材与参数/已验收基准.json，播放其中指向的90.20秒成片。
3. 试听04_生产工程/第一期/第二版试听/ep01_纯中文_柔和试听.wav，再听首集完整纯配音。
4. 阅读所选集的Markdown和JSON，而不是先把100集全部塞进上下文。
5. 按素材清单准备该集真实图片和录音，再计算时间轴并渲染。
6. 交付成片、纯配音、混音、SRT、实际时间轴、素材来源和验收报告。

规则发生冲突时，优先级为：用户最新明确要求 > 用户已验收成片与本包已验收参数 > 本手册 > 单集剧本建议。当前包已移除旧双语稿和历史生产入口。

当前确定的产品方向：

- 睡前系列只用中文。英语学习系列后续另行规划，不在这些成片中穿插英文、词汇解释、跟读或考试。
- 沿用已确认的柔和晓晓音色，不擅自换成其他母语、其他人物或更硬的播音声。
- 手绘水彩绘本、低饱和暖灯与灰蓝夜色，竖屏9:16。
- 多数情境镜头以8–12秒为起点；短动作允许约5–6秒；末段可15–20秒。这是剪辑建议，不是机械定时器。
- 保留约3%的慢推拉、0.96秒叠化、温柔音乐与轻微环境声。
- 局部微动在本地制作。用户明确暂不考虑收费Runway；默认不调用任何新增收费图生视频服务。
- 不增加片头口号、醒目的文字动画、关注点赞、提问或结尾单词复习。
- 不把内容描述成已被证实的治疗、助眠或英语学习方法。

## 3. 接收AI需要的能力与默认执行方式

接收方需要能读写解包文件、运行Python/FFmpeg，并有可以生成或编辑水彩插画的图像工具。没有图像生成工具时，可以先完成剧本、清单和音轨；不能用九张相同参考图冒充当前故事已完成的分镜。只有文本能力时可提供制作指令，实际视频仍需媒体执行环境。

已经确认的选型不需要再次逐项征求意见。用户指定集数后，可以准备目录、读取该集、制作可逆素材、生成试听、合成和检查。遇到真实缺失的服务权限、无法获得的音色或会产生新增付费的步骤，应说明具体阻塞，继续其他独立工作。不得无声改换收费视频服务。

精确复现首集可以完全使用已有媒体，不需要联网、不需要新生成图片、不需要再次请求TTS。制作新集时，只有新配音合成和图像生成需要相应工具；本地合成、混音和编码不向视频生成平台提交任务。

## 5. 环境安装与离线复现

已验证环境为Windows x64、Python 3.10、FFmpeg 9.0.2。主依赖：edge-tts 7.3.1、NumPy 2.2.6、Pillow 11.2.1；间接依赖精确版本见requirements.lock.txt。

包内Windows FFmpeg用于视频编码，重建入口需要Python 3.10。Python本身不随包分发，接收机需要已有Python。离线wheel只适用于Windows x64的Python 3.10；其他Python或系统应下载与自身平台匹配的依赖，不能把CP310 Windows轮子硬装到其他平台。

在04_生产工程目录运行，离线安装：

    python -m pip install --no-index --find-links "../03_素材与参数/离线依赖_Windows_Python310" --target .deps -r requirements.lock.txt

需要网络安装时：

    python -m pip install --target .deps -r requirements.lock.txt

程序会把项目内.deps放到导入路径前面，避免修改全局Python包。Windows默认优先使用包内FFmpeg；其他平台使用系统FFmpeg。不要把测试机器的C盘用户目录写入代码。

字体不是成片的必需依赖，因为默认交付无烧录字幕的视频和独立SRT。诊断缩略图可用系统字体或默认字体，不分发微软系统字体来建立依赖。

## 6. 两条清楚的生产路径

### 6.1 只重拼已验收首集

在04_生产工程运行：

    python tools/series_pipeline.py replay --episode 1

该命令从已有九张插画和17条源MP3离线重建配音、时间轴、九段临时视频和成片，并核对已验收视频SHA256。不请求新TTS或新图片。输出为工作工程/ep001/导出/ep001.mp4，不覆盖基准视频。也可运行00_交接入口中的PowerShell脚本，它先离线安装依赖再调用同一入口。首次渲染需本机算力；中间片段会按需生成缓存，不随交付包分发。

### 6.2 从单集剧本生产新集

以下以第002集为例，每次只处理明确指定的一集：

    python tools/series_pipeline.py prepare --episode 2
    python tools/series_pipeline.py tts --episode 2
    python tools/series_pipeline.py build --episode 2

prepare创建工作工程/ep002/project.json、素材清单.json和绘图共用前缀.txt。按第002集的九镜提示词生成真实图片，保存为：

    工作工程/ep002/images/shot_01.png … shot_09.png

图片齐备后：

    python tools/series_pipeline.py render --episode 2
    python tools/series_pipeline.py check --episode 2

输出在工作工程/ep002/导出：ep002.mp4、voice.wav、mix.wav、episode.srt。时间轴在工作工程/ep002/timeline.json。程序遇到缺图会明确报错，不会自动拿样片图充当新剧情。

如果有意修改了剧本JSON，先审阅变化，再运行prepare --refresh；它会保留已有的图路径与微动设置，但台词变化后需要重新确认配图对应关系。配音以文本、音色、语速和音高的散列识别缓存，只重新请求发生变化的句子。

## 7. 剧本格式与使用方法

每集保留两种用途不同的表示：

- 结构化JSON：唯一改稿源，含逐镜旁白、停顿、画面、镜位、绘图提示词与状态；程序直接读取。
- 单集Markdown：由JSON导出的阅读视图，逐镜展示口播和制作提示，不再重复收录一遍全文及一遍表格。

共用音色在03_素材与参数/配音与声音参数.json，画风与提示词规则在共用画风与提示词.json，角色设计在角色设定.json。每集用引用关联它们。需要纯口播TXT时，运行 `python 04_生产工程/tools/export_scripts.py --episode 2 --txt`，输出到工作工程，避免另存100份容易过期的正文副本。

第002–100集各有完整的小情节：一个具体的发现或小困难，一两个温柔的应对动作，再回到休息。不要把它们重写成标题大纲、知识讲解或“先兴奋再强行催睡”的结构。

各集中文字数约216–252字，接近样片。以样片约3.2个中文字/秒的综合口播估算做初步预算，再加停顿与尾声；这个数字只用于排产，不是TTS速度参数，也不代表所有音色的速度。最终必须测量真实音频。

不朗读“镜01”“轻声”“停顿1秒”“Prompt”等制作文字。不要求孩子回答问题、背诵、跟读、屏住呼吸或执行身体操；可以保留低压的躺好、闭眼邀请，不检查孩子是否做到了。结尾只留下温柔陪伴和晚安。

## 8. 主角、客串与场景连续性

皮皮的固定锚点：

- 小灰兔、圆脸、粉色小鼻子、长而柔软下垂的耳朵。
- 深蓝色睡帽，淡黄小星星与黄色帽球。
- 暖黄色毛毯，橙色胡萝卜玩偶，暗绿色叶片。
- 木床、奶油色枕头、暖色床头灯、木窗、米色叶纹窗帘。
- 暖灯下灰毛呈暖灰，不是随镜头变成白兔、棕熊或另一只角色。

床在左/下，窗在右/上，灯从左下方给出暖光，是首集房间锚点。新集可以在门廊、窗台、花园之间切换，但同一个房间内的床窗关系不能随意镜像翻转。

朋友设定见03_素材与参数/角色设定.json。现有角色图只有皮皮和首集场景；客串目前提供的是文字设计锚点，不伪称已经生成了伙伴参考图。首次制作某伙伴时，先做其参考图，确认造型后贯穿后续镜头与集数。

参照图的角色要标清：人物身份参考、画风参考、场景布局参考不是同一个用途。户外镜头用皮皮图锁定身份和笔触，但不要把卧室家具一起复制到花园中。

## 9. 插画生成与素材命名

1. 先看参考成片与九镜缩略图；皮皮身份参考直接使用第二版/图片/shot_01.png，不另存相同副本。
2. 读取本集完整口播，理解动作和地点；再逐镜生成单张竖图。
3. 用“本集共用画风前缀＋角色锚点＋当前镜头追加提示词”，一次生成一个画面。
4. 先检查头脸、耳朵、帽子、毛毯、玩偶、爪子数量与空间关系，再接受图片。
5. 保存原图与生成提示词，按shot_01.png到shot_09.png编号，避免按创建时间排序。
6. 图片中不生成字幕或水印。字幕后期单独生成，避免画面出现假文字。
7. 保留少量镜头运动裁切余量，不让脸部贴边，避免生成图的主要动作被9:16裁切掉。

推荐暖灯、灰蓝、米黄、柔暗橄榄绿的水彩关系。纸纹应该细而连续，不是覆盖一层脏噪点。避免高饱和霓虹、纯白发光、强对比黑影、镜头内每个点都闪动。

不要为了每个动词都动起来而增加成本。用“打哈欠后的姿态”“整理好的被角”“已安放的玩偶”就能配合台词。需要复杂连续动作时属于另一条制作路线，本系列当前默认不进入收费图生视频。

## 10. 已确认的配音方案

| 项目 | 锁定值 |
| --- | --- |
| 服务入口 | Microsoft Edge在线语音，由edge-tts调用 |
| 音色ID | zh-CN-XiaoxiaoNeural |
| rate | -25% |
| pitch | -2Hz |
| volume | +0% |
| 语言 | 中文，单一讲述者 |
| 输出源 | 按句MP3与元数据保留 |
| 后期工作格式 | 48kHz、单声道、16bit PCM WAV |
| 已确认试听 | 第一集第二版试听/ep01_纯中文_柔和试听.wav |

试听WAV是声音基准，不是一个可以直接替换任意文字的“声音克隆模型”。新增台词仍需调用相同音色合成。不要把20秒试听循环拼成90秒，也不要用其他声音再套一次滤镜冒充原音色。

edge-tts本方案只使用实际支持的rate、pitch、volume，不假定存在“温柔模式”“妈妈情绪”“强制耳语”等可用按钮，也不传不受支持的自定义SSML。柔和来自声线、自然节奏和后期的轻微音色整理。

TTS逐句保存，缓存键包括：文字、音色ID、rate、pitch。改变其中任何一项都使对应句子的缓存失效。音频成功与否以真实返回数据和可解码为准，空文件不能记为成功。

当前首集17条源录音已全量附带，其中四条直接复用用户认可试听中的源MP3。首集离线重做无需请求网络。新集的在线语音需要网络权限，账号或服务可用性以接收方实际环境为准，不保证第三方接口永远不变。

## 11. 配音预处理的准确算法

从每条源MP3解码到48kHz、单声道float32。先确认非静音，再做保守的首尾留白整理：

1. 取源波形最大绝对值peak。
2. 有声判定阈值为max(0.0025, peak×0.008)。
3. 找到首个与最后一个超过阈值的样本。
4. 起点向前保留0.11秒，终点向后保留0.16秒；限制在文件真实范围内。
5. 不剪字头，不把气口全部切掉，不逐字机械裁切。

响度整理：

- 用绝对幅度大于peak×0.03的样本，计算active_rms。
- gain取min(0.105/active_rms, 0.72/当前片段峰值)。
- 把波形乘以gain；保存前检查绝对值小于1。
- 这里的0.105是活跃样本RMS目标，不是整片LUFS；0.72是片段峰值约束，不是设备播放音量。

完整干声组装后，仅应用一次：

    highpass=f=65,equalizer=f=3200:t=q:w=0.8:g=-2

含义：65Hz高通，约3.2kHz附近宽缓降低2dB，轻微收住尖锐感。参数来自已认可试听。不要不断重复处理、过度降噪、加大混响、压成很重的低音，或把发音清晰度当成“硬”全部削掉。

生产过程中区分处理前WAV、处理后纯配音WAV与混音WAV。交付保留源MP3、处理后纯配音与混音；处理前WAV可由源MP3重建，不在剪辑包重复存放。

## 12. 停顿、字幕与真实时间轴

首集：

- 开头1秒画面和音乐先建立，再进入旁白。
- 常规句间额外停顿0.72秒。
- 原五段落结束额外停顿0.95秒。
- 收尾句间约1.1秒。
- 最后一句后约8秒尾声。
- 整体向25fps帧网格补齐，最多额外增加不足0.04秒静音。

新集使用各自JSON中的pause_after_s。分句内天然停顿已经在音频中；补停顿时不要重复加出过长空白。需要调整时先试听，再改配置。

字幕以每句真实解码后的时长定位。当前实现起点约在句片段开头后0.07秒，终点约在尾部前0.10秒，作为可复核的初始字幕；不按中文字数平均分摊整片时长。对每条字幕检查起点小于终点、排序不重叠、末条不越过视频。

镜头切点在相邻语句之间的空隙附近，按语义选择。先把镜头边界放到最近的1/25秒，再计算视频重叠。不要先定90秒，再截短所有语音适配。

## 13. 慢推拉的做法

静态镜头源图先按比例放大并裁切为2160×3840，使用zoompan输出1080×1920。

- 推进：z = 1 + 0.03×frame/(frames−1)。
- 拉远：z = 1.03 − 0.03×frame/(frames−1)。
- 中心点保持在(iw−iw/zoom)/2、(ih−ih/zoom)/2。
- frames必须包含本镜真正可见时长与转场预留。
- 输出25fps、SAR=1、yuv420p。

高一些的中间分辨率用于减轻慢移动的像素跳动。不是为了把几乎静止的图放大到明显裁脸。局部微动镜头可以固定机位；整片不需要每一镜都同时推拉和形变。

## 14. 本地微动的能力范围

本版做的是二维局部微动：给少数区域轻微亮度变化或网格形变。它不生成新的连续肢体动作，不等同于自然的揉眼、说话、转身或图生视频。

首集星光：

- 中心约(0.695W,0.17H)，半宽0.055W，半高0.035H。
- 用高斯柔边限定区域，亮度增量上限约2.5%。
- 周期约7秒，平滑变化，无突然闪亮。

首集被面近景：

- 1080×1920帧，网格约48像素一步，BICUBIC插值。
- 中心约(0.57W,0.70H)，横向尺度0.29W，纵向尺度0.13H。
- y=0.58H以上保持稳定，约0.08H内渐入，避免脸与眼睛跟着被子变形。
- 周期6秒，最大源坐标位移约9像素；并非整只兔子上下挪动9像素。

首集远景被面：

- 中心约(0.53W,0.585H)，尺度0.20W与0.075H。
- 上方约0.515H固定，渐入宽约0.045H。
- 周期6秒，最大位移约4像素，更轻、更慢。

首集叶片：

- 窗框左侧约0.22W以前固定，约0.12W范围内渐入。
- 中心约(0.65W,0.34H)，尺度0.38W与0.28H。
- 横向幅度上限约4像素，约5秒周期，并随镜头推进慢慢衰减。
- 源坐标限制在画面内，避免右边缘露出黑线。

这些坐标只对应首集具体图片。新图必须重新看图标定，不能把数值直接贴到任何兔子或叶片上。脸、眼睛、鼻子、道具边缘和木窗应稳定。无法可靠区分区域时，使用慢推拉就够了。

## 15. 通用程序如何启用新图微动

新集默认motion=camera，表示有镜头运动，不是假装人物已做动画。需要局部微动时，在工作工程/epNNN/project.json的对应场景填写local_motion，并把motion改为local。

一个被面区域的配置示意：

    "motion": "local",
    "local_motion": {
      "type": "displacement",
      "cx": 0.57,
      "cy": 0.70,
      "sx": 0.29,
      "sy": 0.13,
      "axis": "y",
      "amplitude_px": 5,
      "period_s": 6,
      "fixed_above": 0.58
    }

cx/cy/sx/sy是相对画幅的数值。这个例子不是新图的自动正确答案，需逐镜确认。通用变形会让边缘位移归零，并限制源坐标在图内。幅度不得超过9像素，周期不短于5秒。

小星光可以用type=glow，指定cx/cy/sx/sy，gain不超过0.025，周期建议7秒。不要把整张天空变成呼吸灯。每次先生成一个5秒局部效果看边缘，再应用到全镜头；一次性哈欠不应倒放或循环。

## 16. 叠化的帧数与时间公式

统一25fps，所以0.96秒=24帧；每侧0.48秒=12帧。这样可以把转场精确放到整数帧上。

设第i个镜头在最终主时间轴中的长度为Di，主时间轴开始位置为Si：

- 第一镜渲染长度：D1 + 0.48。
- 中间镜渲染长度：Di + 0.96。
- 最后一镜渲染长度：Dn + 0.48。
- 第i镜开始与前镜交叠的xfade offset：Si − 0.48。
- 相邻镜叠化持续时间0.96秒。
- 九镜源片段总长，比最终视频多8×0.96=7.68秒；重叠后刚好回到90.20秒。

画面预留重叠，音频主时间轴不缩短。禁止直接把九段各渲染Di秒后再叠化，那会把整片缩短7.68秒并切掉尾部。

各输入先统一fps、SAR、time_base、像素格式和起始PTS。不同time_base是xfade常见失败原因。最后一镜末4秒渐暗到0x182232深夜蓝，不突然切黑。

## 17. 音乐、环境声与混音

包内music.wav与room_night.wav都是本地程序生成的源音频，首集沿用它们。音乐为稀疏柔和的分解音，环境声为轻柔低通噪声，不是第三方歌曲或下载的森林录音。算法在episode_pipeline.py的sound_bed函数中保留。

音乐大约每12秒换一组和声，音符之间约2.7秒；不加入鼓点、突然高音、叮铃爆点。原生成音乐RMS约0.0045，环境声RMS约0.00065。它们是源波形的幅度参考，不是剪辑软件音量滑块百分比。

混音顺序：

1. 先把人声单独听清，确认每句尾音完整。
2. 读入音乐与环境声，取与完整音轨相同的长度。
3. 音乐/环境声前2秒淡入，末5秒淡出。
4. 将背景加在人声下面，导出mix.wav。
5. 检查样本峰值与削波，实际用手机外放试听中间段与结尾。
6. 结尾淡出以后，不要再对整个文件做无条件增益抬升。

新集超出源音乐长度时，可按同一sound_bed算法生成更长的连续音床，不随意换成不同风格的音乐。不要把一个很短音效生硬拼成整片循环。

最终音量还取决于用户设备，文件峰值不是扬声器声压。本包不把音量数值写成健康或助眠保证。

## 19. 验收：技术通过与听感通过分开记录

技术检查：

- 语音文本与剧本一致，没有漏句、重复、舞台指令或英文混入。
- 字幕起止合法、单调排列、不越过视频。
- 视频完整解码，尺寸、帧率、帧数、时长与时间轴相符。
- 原始与混音样本无削波，结尾尾音与淡出完整。
- 九张真实图片齐备，没有占位图、黑帧、边缘黑线或错误拉伸。
- 动态区域边缘自然，脸、眼睛、帽子和玩偶没有变形漂移。

主观审片：

- 声线、句尾和拼接是否像同一个自然的讲述者。
- 留白是否舒服，有没有为了“慢”把句子拖得松散。
- 音乐是否盖字，单个音符是否突然突出。
- 画面是否对应当下台词，是否在一句话最需要看清动作时过早换图。
- 后半段是否平静，最后是否给了足够的离开声音的时间。

程序检查通过，不等于有人完整听看了影片。第001集已获用户明确认可，验收记录在已验收基准.json。第002–100集不得在未生产前标为成片通过。

## 20. 缓存、修改与重跑范围

只改台词：更新所选集JSON与项目，重新TTS变化句，再build、render、check。字幕和时间轴必须随新录音更新。

只改图片：替换对应真实图片，重新render、check，复用未变化的语音。图片构图变化后，清掉旧的局部微动假设或重新标定。

只改音乐混音：重新build、render、check。不要重新生成全部插画。

只改镜头运动：重新渲染受影响片段，再拼接成片。缓存包含图像、镜头数据和程序版本，避免把旧效果误当新结果。

修改程序后，旧片段缓存可能失效，这是为了保证结果与代码一致。不要删除源录音和原图来“清缓存”；保留这些最耗生成时间的素材。

## 21. 常见故障与处理

| 现象 | 先检查什么 | 正确处理 |
| --- | --- | --- |
| 中文突然变硬或像换人 | voice、rate、pitch、缓存元数据 | 先对照已认可试听，不擅自换音色 |
| TTS连接失败 | 网络权限、服务返回、超时、可用音色 | 保留源文本和已成功缓存；记录真实错误，不把空音频当成功 |
| 语速与预算不同 | 真实WAV时长 | 重算时间轴，不强行压到90秒 |
| 英文又出现在片中 | 读错历史双语稿 | 回到本集JSON中的narration_lines |
| 背景盖字 | 人声清晰度与背景实际幅度 | 先调人声，再降低背景，不只看百分比 |
| 结尾被切 | 画面预留与xfade重叠 | 按0.48/0.96秒公式补足片段长度 |
| xfade报错 | fps、time_base、SAR、像素格式 | 统一为本手册值，再拼接 |
| 微动露黑边 | 源坐标超界、区域贴边 | 限制坐标，边缘位移归零，或退回慢推拉 |
| 被子动、脸也变形 | fixed_above和区域尺度 | 固定头部，减小区域和位移，先看短样片 |
| 字幕抢先或拖尾 | 分句真实时长与首尾留白 | 按音轨定位并人工复核，不按字数均摊 |
| 换电脑找不到文件 | 绝对路径、未解包、漏素材 | 从包根按相对路径读文件，先跑文件校验 |
| 离线pip安装失败 | Python版本、平台与wheel标签 | Win64+Py3.10使用随包轮子，其他环境准备兼容依赖 |
| 字体缺失 | 是否误开启烧录字幕 | 当前成片不需要字体；诊断缩略图用可用字体 |
| 没有新集图片 | 是否只读了剧本未生产素材 | 按九镜提示词生成，不重复复制首集图片充数 |

## 22. 新集JSON约定与素材边界

结构化剧本schema_version=2，包含episode、title、theme、setting、guest、character_names、shared_config和shots。每镜保留id、title（画面）、narration_lines、pause_after_s、camera、image_prompt、motion_hint等。共用画风、角色与微动建议由引用展开；append_common_prompt_rules=true时，单镜提示词末尾追加共用image_prompt_rules。series_pipeline.py的catalogue()负责完整展开，prepare会输出合并后的绘图前缀与素材清单。

initial_duration_budget_s是预估；actual_duration_s在后99集为null。只有实际生成、测量并检查后，才能写实测时长。

新集生成的图片必须能与本镜title（画面）和台词对上。参考图是身份与风格约束，不是剧情素材的万能替代品。客串未在当前镜头出现时，不自动把所有朋友画进图里。

在工作工程中，motion=camera表示仅镜头运动；motion=local且提供local_motion时，才执行新图的局部动画。首集reference_geometry=true允许使用已校准首集坐标，新集不要仿填这个标记来跳过标定。
